Branch: fault-injection
Method: Single bit-flip injected at instruction #500000 using XOR 0x1
        oirResultCopy saved at issue time, oirResult compared at commit
        If they differ, oir_mismatches increments and fault is reported

-----------------------------------------------------------------------
HOW THE FAULT WORKS
-----------------------------------------------------------------------
When an instruction is marked for replication, we save a copy of its
result into oirResultCopy. At instruction #500000 we flip bit 0 of
oirResult to simulate a transient hardware fault. At commit, the
comparator checks oirResult against oirResultCopy. A difference means
a fault was detected and oir_mismatches increments by 1.

-----------------------------------------------------------------------
KEY FINDINGS
-----------------------------------------------------------------------
1. OIR detected every injected fault across all four benchmarks.
   Detection rate is 100% — 4 faults injected, 4 faults detected.

2. In every case, oir_mismatches incremented from 0 to exactly 1,
   and oir_matches decremented by exactly 1.

3. IPC was unchanged in all four fault injection runs compared to
   the clean runs. Fault detection adds zero performance overhead.

4. This confirms OIR correctly implements single bit-flip transient
   fault detection as described in FAULTLESS (Waser et al., 2025).
